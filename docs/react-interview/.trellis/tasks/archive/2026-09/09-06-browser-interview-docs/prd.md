# 重构浏览器篇前端面试文档

## Goal

将 `/Users/zz/Downloads/2024年前端面试---浏览器篇.md` 从内容重复、层级混杂、格式噪声较多的资料，重构为一份适合前端中高级面试复习与面试现场表达的浏览器专题文档。文档需要兼顾知识深度、通俗解释、回答结构和图文理解，并产出到当前项目目录。

## Background

- 源文档共约 1,868 行，包含浏览器缓存、Cookie / Web Storage、URL 到页面展现、网络连接、TLS、浏览器渲染、回流重绘、进程线程、Worker / Service Worker、SSR / CSR 等主题。
- 源文档包含约 34 个远程图片引用，但没有 Mermaid 图；部分内容来自富文本导出，存在 `<font>` 标签、重复标题、编号不连续、问答与正文交叉、个别术语和示例不严谨等问题。
- 当前仓库已经有一套 React 面试文档，风格偏向“总览 → 心智模型 → 分层深入 → 高频问答”，并使用 Mermaid / SVG 作为结构图示；本次产物应保持 Markdown 兼容性，同时独立成篇。

## Requirements

### R1. 内容重组

按面试认知链路重排为清晰章节，至少覆盖：

1. 浏览器整体架构与多进程模型；
2. 从 URL 输入到页面展现的完整链路；
3. HTTP 缓存：强缓存、协商缓存、启发式缓存、ETag / Last-Modified、刷新行为与工程策略；
4. 浏览器端数据存储：Cookie、localStorage、sessionStorage、IndexedDB，以及 Session / Token 的边界；
5. 网络基础：DNS、TCP 三次握手与四次挥手、TLS、HTTP 请求与响应；
6. 渲染流水线：DOM / CSSOM、Render Tree、Layout、Paint、Composite、GPU 与渲染进程的协作；
7. JavaScript、CSS、图片、字体对解析和渲染的阻塞关系，以及关键渲染路径优化；
8. 回流 / 重排、重绘、合成层与性能优化；
9. Worker、SharedWorker、Service Worker 的区别与适用场景；
10. SSR 与 CSR 的差异及面试回答角度。

### R2. 面试表达深度

每个核心主题尽量包含：

- 一句话结论；
- 通俗解释；
- 工作流程或因果链；
- 关键边界、常见误区和面试官追问；
- 工程实践或优化建议；
- 适合 30 秒、2 分钟回答的表达要点（对于高频主题）。

不得只堆砌概念；需要明确“为什么”“什么时候发生”“谁负责”和“如何验证”。

### R3. 图文结合

- 使用 Mermaid 表示流程、时序、决策关系和层级关系，至少覆盖：URL 到首屏、缓存决策、渲染流水线、进程 / 线程关系、TCP / TLS 连接中的关键步骤。
- 对 Mermaid 不适合表达或需要稳定视觉布局的内容，提供独立 SVG 图；SVG 应放在 `assets/` 下并由 Markdown 引用。
- 图示必须服务于解释，配套文字说明“看图重点”，避免只放装饰图。
- 文档在 Typora / GitHub 风格 Markdown 下应可读；远程图片只在确实有价值且可访问时保留，优先使用本地 SVG / Mermaid 替代原始 OCR 截图。

### R4. 语言与格式

- 使用简体中文，技术术语保留英文，首次出现时给出中文解释。
- 清理源文档中的富文本 HTML 标签、重复内容、无意义颜色标记和断裂编号。
- 统一标题层级、代码块、表格、提示块和术语写法。
- 示例代码必须语法正确，HTTP 头部示例使用合法格式，并明确哪些行为由浏览器、服务器或代理完成。

### R5. 产物边界

- 生成一份可直接阅读的主文档，建议命名为 `browser-interview-guide.md`。
- 需要的 SVG 资源放入当前项目的 `assets/` 目录，文件名使用英文 kebab-case。
- 不修改现有 React 专题文档，不覆盖源文件，不依赖外部构建步骤才能阅读。
