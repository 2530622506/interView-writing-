## `手写 Promise.all`

**题目要求**

- 接收可迭代对象，普通值也要处理
- 所有 Promise resolve 后按原始顺序返回结果数组
- 任意一个 reject 立即 reject 并携带原因
- 空数组输入直接 resolve([])

**代码架子**

```js
Promise.myAll = function (promises) {
  // TODO
}
```

**参考答案**

```js
Promise.myAll = function (promises) {
  return new Promise((resolve, reject) => {
    // Array.from 处理所有可迭代对象（Set、Generator 等）
    const tasks = Array.from(promises)
    const result = []
    let count = 0

    // 空数组提前短路，避免进入 forEach 后永远不 resolve
    if (tasks.length === 0) return resolve([])

    tasks.forEach((promise, index) => {
      // Promise.resolve 包裹：处理传入普通值（非 Promise）的情况
      Promise.resolve(promise).then(
        res => {
          result[index] = res   // 按 index 赋值，保证顺序（不用 push）
          count++
          if (count === tasks.length) {
            resolve(result)     // 全部完成才 resolve
          }
        },
        reason => {
          reject(reason)        // 任意一个 reject 立即 reject
        }
      )
    })
  })
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `Array.from` | 兼容所有可迭代对象 |
| `result[index]` | 保证结果顺序，而非 push |
| `Promise.resolve(promise)` | 兼容普通值传入 |
| `return resolve([])` | 空数组加 return，逻辑更严谨 |
| `===` | 严格相等，避免隐式类型转换 |

**常见错误**

- `==` 替代 `===`（宽松比较）
- 空数组 `resolve([])` 后忘记 `return`，逻辑不严谨
- 用 `push` 替代 `result[index]`，结果顺序可能错乱

## `手写 LRU Cache`

**题目要求**

- `get(key)`：返回缓存值，不存在返回 -1，访问后更新为最近使用
- `put(key, value)`：写入缓存，超出容量时淘汰最久未使用的 key
- get 和 put 时间复杂度均为 O(1)

**代码架子**

```js
class LRUCache {
  constructor(capacity) {}
  get(key) {}
  put(key, value) {}
}
```

**参考答案**

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity
    // Map 的迭代顺序 = 插入顺序，天然模拟 LRU 队列
    // 最久未使用 → 队头（keys().next()）
    // 最近使用   → 队尾（最新 set）
    this.cache = new Map()
  }

  get(key) {
    if (!this.cache.has(key)) return -1

    const value = this.cache.get(key)
    // delete + set：把 key 移到队尾（标记为最近使用）
    this.cache.delete(key)
    this.cache.set(key, value)

    return value
  }

  put(key, value) {
    if (this.cache.has(key)) {
      // key 已存在：先删旧的，后面统一 set，size 不变，不需要淘汰
      this.cache.delete(key)
    } else if (this.cache.size >= this.capacity) {
      // key 不存在且已满：淘汰队头（最久未使用）
      // keys().next().value 取迭代器第一个 key，即最旧的
      this.cache.delete(this.cache.keys().next().value)
    }
    // 插入到队尾（最近使用位置）
    this.cache.set(key, value)
  }
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `Map` 插入顺序 | 天然维护 LRU 顺序，O(1) get/set/delete |
| `delete + set` | 移到队尾，模拟"最近使用" |
| `keys().next().value` | 取队头（最旧 key），O(1) |
| `if/else if` 结构 | key 存在时不触发淘汰，避免 size 计算错误 |

**常见错误**

```js
// ❌ 错误写法：先删已有key，再用 > 判断
if (this.cache.has(key)) this.cache.delete(key)
if (this.cache.size > this.capacity) { ... }  // size 已减1，永远不会触发淘汰

// ✅ 正确：if/else if，两个分支互斥
if (this.cache.has(key)) {
  this.cache.delete(key)
} else if (this.cache.size >= this.capacity) {
  this.cache.delete(this.cache.keys().next().value)
}
```

## `手写 useDebounce Hook`

**题目要求**

- `value` 变化后，延迟 `delay` 毫秒才更新返回值
- delay 内 value 再次变化，重新计时
- 组件卸载时清理定时器

**代码架子**

```js
function useDebounce(value, delay) {
  // TODO
}
```

**参考答案**

```js
import { useState, useEffect } from 'react'

function useDebounce(value, delay) {
  // 存储防抖后的值，初始值与 value 一致（首次渲染无延迟）
  const [debouncedValue, setDebouncedValue] = useState(value)

  useEffect(() => {
    // value 或 delay 变化时，重新启动定时器
    const timer = setTimeout(() => {
      setDebouncedValue(value)
    }, delay)

    // cleanup：value/delay 变化或组件卸载时，清除上一个定时器
    // 这正是防抖的关键：连续变化时，只有最后一次会触发
    return () => clearTimeout(timer)
  }, [value, delay]) // 依赖 value 和 delay

  return debouncedValue
}

export default useDebounce
```

**使用示例**

```js
function SearchBox() {
  const [input, setInput] = useState('')
  const debouncedInput = useDebounce(input, 500)

  useEffect(() => {
    // 只有用户停止输入 500ms 后才触发搜索
    if (debouncedInput) fetchSearch(debouncedInput)
  }, [debouncedInput])

  return <input onChange={e => setInput(e.target.value)} />
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `useState(value)` 初始值 | 首次渲染直接返回 value，无延迟 |
| cleanup `clearTimeout` | 连续变化时清除旧 timer，实现防抖 |
| 依赖数组 `[value, delay]` | delay 变化也需要重新计时 |
| 变量命名 | `debouncedValue` 比 `count` 语义清晰 |

**常见错误**

- 忘记 `return debouncedValue`（函数没有返回值）
- 变量命名语义不清（`count`、`state` 等）
- useEffect 依赖数组缺少 `delay`

## `手写 deepClone（深拷贝）`

**题目要求**

- 基本类型直接返回
- 普通对象/数组递归拷贝
- 循环引用处理（WeakMap）
- 特殊对象：Date、RegExp
- null 和函数的处理

**代码架子**

```js
function deepClone(obj, hash = new WeakMap()) {
  // TODO
}
```

**参考答案**

```js
function deepClone(obj, hash = new WeakMap()) {
  // 基本类型（number/string/boolean/undefined）和函数：直接返回原值
  // null 的 typeof 是 'object'，需要单独排除
  if (typeof obj !== 'object' || obj === null) return obj

  // 循环引用检测：如果已经克隆过，直接返回克隆结果
  // 放在特殊对象判断之前，避免重复创建
  if (hash.has(obj)) return hash.get(obj)

  // 特殊对象：不能递归属性，直接用构造函数复制
  if (obj instanceof Date) return new Date(obj)
  if (obj instanceof RegExp) return new RegExp(obj)

  // 保持数组/对象类型
  const res = Array.isArray(obj) ? [] : {}

  // 提前存入 hash，防止循环引用时无限递归
  hash.set(obj, res)

  // for...in 遍历对象所有可枚举属性（含继承），hasOwnProperty 过滤继承属性
  // 也可用 Object.keys(obj)，只遍历自身可枚举属性（更推荐）
  for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
      res[key] = deepClone(obj[key], hash) // 递归克隆每个值
    }
  }

  return res
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `typeof obj !== 'object'` | 字符串对比，非构造函数对比 |
| `obj === null` | null 的 typeof 是 'object'，需单独排除 |
| `hash.set` 在循环前 | 先记录再递归，防止循环引用死循环 |
| `WeakMap` 而非 `Map` | key 为对象引用，对象回收时自动清除，无内存泄漏 |
| `for...in` + `hasOwnProperty` | 过滤原型链上的属性 |

**常见错误**

```js
// ❌ typeof 与构造函数比较，永远 false
if (typeof obj !== Object)

// ❌ null 判断方向反了，导致所有值都提前 return
if (obj !== null) return obj

// ❌ for...of 不能遍历普通对象
for (const item of obj)
```

## `图片懒加载（IntersectionObserver）`

**题目要求**

- 图片用 `data-src` 存真实地址，`src` 为空
- 图片进入视口时赋值 `src`
- 已加载图片不重复处理
- 使用 `IntersectionObserver`

**代码架子**

```js
function lazyLoad(images) {
  // TODO
}
```

**参考答案**

```js
function lazyLoad(images) {
  const observer = new IntersectionObserver(
    (entries, obs) => {
      entries.forEach(entry => {
        // 关键判断：只处理进入视口的元素
        // IntersectionObserver 在元素离开视口时也会触发回调，必须过滤
        if (!entry.isIntersecting) return

        const img = entry.target
        const src = img.dataset.src

        // 防御：data-src 为空时跳过，避免 src="" 触发 404 请求
        if (!src) return

        img.src = src

        // 赋值后立即停止观察，已加载图片不重复处理
        obs.unobserve(img)
      })
    },
    {
      // 提前 100px 开始加载，用户滚动时图片已就绪，体验更流畅
      rootMargin: '100px',
      // 图片露出 10% 时触发（不需要完全进入视口）
      threshold: 0.1,
    }
  )

  // 注册所有图片
  images.forEach(img => observer.observe(img))
}
```

**使用示例**

```html
<!-- HTML：src 留空，真实地址放 data-src -->
<img data-src="https://cdn.example.com/photo.jpg" alt="商品图" />

<script>
  const imgs = document.querySelectorAll('img[data-src]')
  lazyLoad(Array.from(imgs))
</script>
```

**关键点**

| 点 | 说明 |
|---|---|
| `entry.isIntersecting` | 必须判断，离开视口也会触发回调 |
| `obs.unobserve(img)` | 加载后停止观察，避免重复赋值 |
| `rootMargin: '100px'` | 预加载区域，提升用户体验 |
| `dataset.src` 空值防御 | 避免 `src=""` 发出无效请求 |

**与 scroll 监听方案对比**

| | IntersectionObserver | scroll 监听 |
|---|---|---|
| 性能 | 浏览器原生，无主线程开销 | 需节流，频繁触发 |
| 精准度 | 浏览器级别精确 | 需手动计算 getBoundingClientRect |
| 代码复杂度 | 简单 | 需节流 + 手动计算 |
| 兼容性 | IE 不支持（现代浏览器 ✅） | 全兼容 |

## `手写 throttle（节流）`

**题目要求**

- `fn` 在 `wait` 毫秒内最多执行一次
- 连续触发时，第一次立即执行（leading），之后每隔 wait 触发一次
- 停止触发后，最后一次未执行的调用需要补发（trailing）
- 使用时间戳方案

**代码架子**

```js
function throttle(fn, wait) {
  // TODO
}
```

**参考答案**

```js
function throttle(fn, wait) {
  let lastTime = 0   // 上次执行时间戳
  let timer = null   // trailing 补发定时器

  return function (...args) {
    const now = Date.now()
    const remaining = wait - (now - lastTime)  // 距下次可执行还剩多久

    if (remaining <= 0) {
      // 冷却结束：立即执行（leading 调用）
      if (timer) { clearTimeout(timer); timer = null }
      lastTime = now
      fn.apply(this, args)
    } else {
      // 冷却中：重置 trailing 定时器，保留最后一次调用的参数
      // 每次重置都会延迟，直到停止触发后 remaining 毫秒才真正执行
      clearTimeout(timer)
      timer = setTimeout(() => {
        lastTime = Date.now()
        timer = null
        fn.apply(this, args)
      }, remaining)
    }
  }
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `remaining = wait - (now - lastTime)` | 精确计算冷却剩余时间 |
| leading 立即执行 | `remaining <= 0` 时马上调用 |
| trailing 补发 | 冷却中每次调用重置定时器，停止后补发最后一次 |
| `clearTimeout` 在 leading 前 | 避免 leading + trailing 重复执行 |

**与防抖（debounce）区别**

| | throttle 节流 | debounce 防抖 |
|---|---|---|
| 语义 | 固定频率执行 | 停止后才执行 |
| 场景 | 滚动、resize、mousemove | 搜索框、表单提交 |
| 首次触发 | 立即执行 | 延迟执行 |

## `手写 EventEmitter（发布订阅）`

**题目要求**

- `on(event, fn)` — 订阅，同一事件可多次订阅
- `off(event, fn)` — 取消订阅，fn 不存在不报错
- `emit(event, ...args)` — 触发，按订阅顺序调用所有回调
- `once(event, fn)` — 订阅一次，触发后自动取消

**代码架子**

```js
class EventEmitter {
  constructor() {}
  on(event, fn) {}
  off(event, fn) {}
  emit(event, ...args) {}
  once(event, fn) {}
}
```

**参考答案**

```js
class EventEmitter {
  constructor() {
    this.events = {}  // { eventName: [fn1, fn2, ...] }
  }

  on(event, fn) {
    // 注意：必须是 this.events[event]，不是 this.events
    if (!this.events[event]) {
      this.events[event] = []
    }
    this.events[event].push(fn)
  }

  off(event, fn) {
    const fns = this.events[event]
    // 事件不存在或 fn 不在列表中，静默处理不报错
    if (fns) {
      this.events[event] = fns.filter(f => f !== fn)
    }
  }

  emit(event, ...args) {
    const fns = this.events[event]
    // 防御：事件不存在时不报错
    if (fns) fns.forEach(fn => fn(...args))
  }

  once(event, fn) {
    // 包装函数：执行原 fn 后立即 off 掉 wrap 本身
    const wrap = (...args) => {
      fn(...args)
      this.off(event, wrap)  // 关键：off 的是 wrap，不是 fn
    }
    this.on(event, wrap)
  }
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `this.events[event]` | 必须带 `[event]`，漏写会覆盖整个 events 对象 |
| `filter` 而非 splice | 不可变操作，避免遍历中修改数组 |
| `once` off 的是 `wrap` | off 传 fn 会失效，因为订阅的是包装后的 wrap |
| emit 防御 `if (fns)` | 避免触发未注册事件时报错 |

**常见错误**

```js
// ❌ 漏写 [event]，把整个 events 覆盖成数组
if (!this.events[event]) this.events = []
this.events.push(fn)

// ✅ 正确
if (!this.events[event]) this.events[event] = []
this.events[event].push(fn)
```

## `手写 Function.prototype.bind`

**题目要求**

- 返回新函数，调用时 `this` 固定为 `thisArg`
- 支持柯里化：bind 时预置部分参数，调用时传剩余参数
- 用 `new` 调用绑定函数时，`thisArg` 失效，`new` 优先
- 维护原函数的 `prototype` 链

**代码架子**

```js
Function.prototype.myBind = function (ctx, ...args) {
  // TODO
}
```

**参考答案**

```js
Function.prototype.myBind = function (ctx, ...preArgs) {
  const fn = this  // 保存原函数引用，避免 Bound 内 this 指向错误

  function Bound(...laterArgs) {
    return fn.apply(
      // new 调用时 this 是 Bound 的实例，优先级高于 ctx 绑定
      this instanceof Bound ? this : ctx,
      [...preArgs, ...laterArgs]  // 合并预置参数和后续参数（柯里化）
    )
  }

  // 维护原型链：new BoundFn() 的实例也是原函数的实例
  // 箭头函数没有 prototype，需要防御
  if (fn.prototype) {
    Bound.prototype = Object.create(fn.prototype)
  }

  return Bound
}
```

**关键点**

| 点 | 说明 |
|---|---|
| `const fn = this` | 保存原函数，Bound 内 this 已变 |
| `this instanceof Bound` | 判断是否 new 调用 |
| `[...preArgs, ...laterArgs]` | 柯里化参数合并 |
| `Object.create(fn.prototype)` | 维护 instanceof 关系 |
| `if (fn.prototype)` | 箭头函数无 prototype，防止报错 |

**new 调用时 ctx 失效原理**

```
new BoundFn() 时：
  1. 创建空对象 {}，原型指向 Bound.prototype（即 fn.prototype）
  2. 将 this 绑定为该空对象执行 Bound
  3. this instanceof Bound === true → 使用 this（new 创建的对象）
  4. ctx 被忽略
```

## `数组扁平化（指定深度）`

**题目要求**

- `flatten(arr, depth = Infinity)` 支持指定展开深度
- `depth = 1` 只展开一层，`depth = Infinity` 全部展开
- 不能用 `Array.prototype.flat`

**代码架子**

```js
function flatten(arr, depth = Infinity) {
  // TODO
}
```

**参考答案**

```js
function flatten(arr, depth = Infinity) {
  const res = []

  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) {
      // 是数组且还有剩余深度：递归展开，depth - 1 控制层数
      res.push(...flatten(item, depth - 1))
    } else {
      // 非数组或已达深度限制：直接放入结果
      res.push(item)
    }
  }

  return res
}
```

**使用示例**

```js
flatten([1, [2, [3, [4]]]])        // [1, 2, 3, 4]
flatten([1, [2, [3, [4]]]], 1)     // [1, 2, [3, [4]]]
flatten([1, [2, [3, [4]]]], 2)     // [1, 2, 3, [4]]
flatten([1, [2, [3]]], 0)          // [1, [2, [3]]]  depth=0 不展开
```

**关键点**

| 点 | 说明 |
|---|---|
| `depth > 0` | 与 `Array.isArray` 同时判断，控制展开层数 |
| `depth - 1` | 每递归一层深度减一，精确控制 |
| `Infinity` 默认值 | 不传 depth 时完全展开 |
| `spread` 展开 | `push(...flatten(...))` 合并结果，避免嵌套数组 |

**其他实现方式**

```js
// reduce 版（更函数式）
function flatten(arr, depth = Infinity) {
  return arr.reduce((acc, item) => {
    if (Array.isArray(item) && depth > 0) {
      acc.push(...flatten(item, depth - 1))
    } else {
      acc.push(item)
    }
    return acc
  }, [])
}
```

## `手写 instanceof`

**题目要求**

- `myInstanceof(obj, Constructor)` 模拟 `instanceof` 行为
- 沿原型链向上查找，找到 `Constructor.prototype` 返回 true
- 基本类型返回 false，null 返回 false

**代码架子**

```js
function myInstanceof(obj, Constructor) {
  // TODO
}
```

**参考答案**

```js
function myInstanceof(obj, Constructor) {
  // 基本类型（number/string/boolean/symbol/bigint/undefined）直接返回 false
  // 函数是对象，需要允许（typeof fn === 'function'）
  if (typeof obj !== 'object' && typeof obj !== 'function') return false

  // null 的 typeof 是 'object'，需要单独排除
  if (obj === null) return false

  // 从 obj 的直接原型开始向上遍历
  let proto = Object.getPrototypeOf(obj)

  while (proto) {
    if (proto === Constructor.prototype) return true
    // 继续向上，直到 proto 为 null（原型链顶端）
    proto = Object.getPrototypeOf(proto)
  }

  return false
}
```

**使用示例**

```js
myInstanceof([], Array)           // true
myInstanceof([], Object)          // true（Array.prototype → Object.prototype）
myInstanceof({}, Array)           // false
myInstanceof(null, Object)        // false
myInstanceof('str', String)       // false（基本类型）
myInstanceof(new String('x'), String)  // true（包装对象）
myInstanceof(() => {}, Function)  // true（函数也是对象）
myInstanceof(() => {}, Object)    // true
```

**关键点**

| 点 | 说明 |
|---|---|
| `typeof !== 'function'` | 函数也要参与判断，不能只判断 `!== 'object'` |
| `null` 单独处理 | `typeof null === 'object'`，必须提前排除 |
| `Object.getPrototypeOf` | 标准方式获取原型，比 `__proto__` 更规范 |
| `while (proto)` | proto 为 null 时退出，返回 false |

**原型链示意**

```
[].__proto__ → Array.prototype
            → Object.prototype
            → null
```

## `手写 curry（柯里化）`

**题目要求**

- 把多参数函数转换为可逐步传参的函数
- 当传入参数总数 >= 原函数 arity（`fn.length`）时执行
- 通用实现，不能写死参数个数

**代码架子**

```js
function curry(fn) {
  // TODO
}
```

**参考答案**

```js
function curry(fn) {
  return function curried(...args) {
    // 参数够了：直接执行
    if (args.length >= fn.length) {
      return fn.apply(this, args)
    } else {
      // 参数不够：返回新函数继续收集，递归累积
      return function (...moreArgs) {
        return curried.apply(this, [...args, ...moreArgs])
      }
    }
  }
}
```

**使用示例**

```js
const add = (a, b, c) => a + b + c
const curriedAdd = curry(add)

curriedAdd(1)(2)(3)     // 6
curriedAdd(1, 2)(3)    // 6
curriedAdd(1)(2, 3)     // 6
curriedAdd(1, 2, 3)     // 6

// this 绑定也保留
function greet(greeting, name) {
  return greeting + ' ' + name + (this.suffix || '')
}
const obj = { suffix: '!' }
curry(greet).call(obj, 'Hello')('World')  // Hello World!
```

**关键点**

| 点 | 说明 |
|---|---|
| `args.length >= fn.length` | 参数达到 arity 立即执行 |
| `curried` 递归 | 每次返回新函数，继续收集剩余参数 |
| `[...args, ...moreArgs]` | 累积所有参数 |
| `fn.apply(this, args)` | 保留 this 绑定，支持 `.call` |
| `fn.length` | 函数形参个数，柯里化的依据 |

## `手写 Promise.race`

**题目要求**

- 返回第一个完成的 Promise 的结果（resolve 或 reject）
- 其他 Promise 结果被忽略（但仍会执行，不取消）
- 空数组：永远 pending
- 第一个 reject 也会立即 reject 整体

**代码架子**

```js
Promise.myRace = function (promises) {
  // TODO
}
```

**参考答案**

```js
Promise.myRace = function (promises) {
  return new Promise((resolve, reject) => {
    // Array.from 兼容所有可迭代对象（Set、Generator 等）
    Array.from(promises).forEach(p => {
      // Promise.resolve 包裹普通值
      Promise.resolve(p)
        .then(item => resolve(item))    // 第一个 resolve 即决定整体
        .catch(reason => reject(reason)) // 第一个 reject 即决定整体
    })
  })
}
```

**与 Promise.all 对比**

| | Promise.all | Promise.race |
|---|---|---|
| 完成条件 | 全部 resolve | 第一个完成（resolve 或 reject） |
| 空数组 | resolve([]) | 永远 pending |
| 失败行为 | 任意一个 reject 即 reject | 第一个 reject 即 reject |

**关键点**

| 点 | 说明 |
|---|---|
| `Array.from` | 兼容可迭代对象，比直接 `forEach` 更健壮 |
| `Promise.resolve(p)` | 处理普通值传入 |
| 状态不可逆 | Promise 一旦 resolve/reject 就锁定，后续调用无效 |

## `手写 new 操作符`

**题目要求**

模拟 `new` 的四个步骤：
1. 创建新对象
2. 新对象的 `__proto__` 指向 `Constructor.prototype`
3. 以新对象为 `this` 执行构造函数
4. 构造函数返回对象时用返回值，否则返回新对象

**代码架子**

```js
function myNew(Constructor, ...args) {
  // TODO
}
```

**参考答案**

```js
function myNew(Constructor, ...args) {
  // 1. 创建新对象，原型指向 Constructor.prototype
  const obj = Object.create(Constructor.prototype)

  // 2. 以 obj 为 this 执行构造函数，属性赋值到 obj 上
  //    注意：必须是 obj，不是 this（this 是 myNew 自己的 this）
  const res = Constructor.apply(obj, args)

  // 3. 构造函数返回对象时用返回值，否则用 obj
  //    返回基本类型（number/string/null）时忽略，仍返回 obj
  return res instanceof Object ? res : obj
}
```

**使用示例**

```js
function Person(name, age) {
  this.name = name
  this.age = age
}
const p = myNew(Person, 'Alice', 25)
p.name              // 'Alice'
p instanceof Person // true

// 返回对象的情况
function ObjC() {
  return { x: 1 }
}
const o = myNew(ObjC)
o.x            // 1
o instanceof ObjC  // false（返回的是手写 return 的对象，不是 this）
```

**关键点**

| 点 | 说明 |
|---|---|
| `Object.create(Constructor.prototype)` | 创建对象并绑定原型链 |
| `Constructor.apply(obj, args)` | **必须用 obj**，不是 this |
| `res instanceof Object` | 返回对象用 res，基本类型用 obj |
| 返回基本类型被忽略 | `return 1` 仍返回 obj，不返回 1 |

**常见错误**

```js
// ❌ apply(this) 导致属性挂到全局
const res = Constructor.apply(this, args)  // this 是 global，不是 obj

// ✅ 正确
const res = Constructor.apply(obj, args)
```

## `手写 compose / pipe`

**题目要求**

- `compose`：从右到左执行，前一个输出是后一个输入
- `pipe`：从左到右执行（compose 的反向）
- 空函数数组返回恒等函数 `x => x`
- 用 `reduce` 实现

**代码架子**

```js
function compose(...fns) {
  // TODO
}
function pipe(...fns) {
  // TODO
}
```

**参考答案**

```js
function compose(...fns) {
  // 空数组返回恒等函数，避免 reduce 无初始值报错
  if (fns.length === 0) return x => x
  if (fns.length === 1) return fns[0]
  // 从右到左：f(g(x))，右边的先执行
  return fns.reduce((f, g) => (...args) => f(g(...args)))
}

function pipe(...fns) {
  if (fns.length === 0) return x => x
  if (fns.length === 1) return fns[0]
  // 从左到右：g(f(x))，左边的先执行
  return fns.reduce((f, g) => (...args) => g(f(...args)))
}
```

**使用示例**

```js
const double = x => x * 2
const addOne = x => x + 1
const square = x => x * x

compose(square, addOne, double)(3)  // 49（double→addOne→square）
pipe(double, addOne, square)(3)     // 49（同顺序，同结果）
compose()(5)                        // 5（恒等）
compose(double)(3)                  // 6
```

**执行过程拆解**

```
compose(square, addOne, double)(3)

reduce 第一步：f = square, g = addOne
  → (...args) => square(addOne(...args))

reduce 第二步：f = 上一步结果, g = double
  → (...args) => square(addOne(double(...args)))

调用(3)：double(3)=6 → addOne(6)=7 → square(7)=49
```

**关键点**

| 点 | 说明 |
|---|---|
| 空数组边界 | 返回 `x => x`，否则 reduce 报错 |
| compose 方向 | `f(g(x))`，新函数在外（右边先执行） |
| pipe 方向 | `g(f(x))`，新函数在外（左边先执行） |
| 两题只差一个字符 | `f(g())` vs `g(f())` |

## `并发控制器`

**题目要求**

- 同时运行的任务数不超过 `max`
- `add` 返回 Promise，任务执行完后 resolve 结果
- 超出并发数的任务进入队列等待，有空位自动执行

**代码架子**

```js
class ConcurrencyScheduler {
  constructor(max) {}
  add(task) {}   // task 是返回 Promise 的函数
  run() {}
}
```

**参考答案**

```js
class ConcurrencyScheduler {
  constructor(max) {
    this.max = max        // 最大并发数
    this.running = 0      // 当前正在运行的任务数
    this.queue = []       // 等待执行的任务队列
  }

  add(task) {
    // add 返回 Promise，调用方可以 .then 拿到结果
    return new Promise((resolve, reject) => {
      // task 和它的 resolve/reject 一起入队
      this.queue.push({ task, resolve, reject })
      this.run()  // 尝试启动任务
    })
  }

  run() {
    // 只要有空位且队列不为空，就启动任务
    while (this.running < this.max && this.queue.length > 0) {
      const { task, resolve, reject } = this.queue.shift()
      this.running++

      task()
        .then(resolve, reject)  // 把任务结果透传给 add 返回的 Promise
        .finally(() => {
          this.running--  // 任务结束，释放一个空位
          this.run()      // 检查队列，启动下一个
        })
    }
  }
}
```

**使用示例**

```js
const scheduler = new ConcurrencyScheduler(2) // 最多同时跑 2 个
const delay = (ms, val) => () =>
  new Promise(r => setTimeout(() => r(val), ms))

scheduler.add(delay(1000, 'A')).then(v => console.log(v))
scheduler.add(delay(500, 'B')).then(v => console.log(v))
scheduler.add(delay(300, 'C')).then(v => console.log(v))
scheduler.add(delay(400, 'D')).then(v => console.log(v))

// 输出：B(500ms) → C(800ms) → A(1000ms) → D(1206ms)
```

**执行过程（max=2，4个任务）**

```
0ms    A(1000ms)、B(500ms) 开始 → running=2，队列=[C,D]
500ms  B 完成 → running=1 → run() 启动 C(300ms) → running=2
800ms  C 完成 → running=1 → run() 启动 D(400ms) → running=2
1000ms A 完成 → running=1
1200ms D 完成 → running=0
```

**关键点**

| 点 | 说明 |
|---|---|
| queue 存 `{task, resolve, reject}` | task 和回调绑定入队，出队时透传结果 |
| add 返回 `new Promise` | 调用方 `.then` 拿到的结果来自任务内部的 resolve |
| while 循环启动 | 一次性填满所有空位，不逐个等 |
| `.finally` 释放空位 | 无论成功失败都释放，再调 run() 启动下一个 |

**扩展：暂停/恢复**

```js
class ConcurrencyScheduler {
  // ... 同上，新增 paused 标志
  constructor(max) {
    this.max = max
    this.running = 0
    this.queue = []
    this.paused = false
  }

  pause() { this.paused = true }
  resume() { this.paused = false; this.run() }

  run() {
    if (this.paused) return  // 暂停时不启动新任务
    while (this.running < this.max && this.queue.length > 0) {
      const { task, resolve, reject } = this.queue.shift()
      this.running++
      task().then(resolve, reject).finally(() => {
        this.running--
        this.run()
      })
    }
  }
}
```

**核心难点**

add 不直接执行 task，而是返回一个 Promise，把 task 的结果和这个 Promise 的 resolve 绑定在一起。想清楚这一点，整道题就通了。

## `数组转树`

**题目要求**

给定一个扁平数组，每个节点有 `id` 和 `parentId`，根节点的 `parentId` 为 `null`，将其转换为树形结构。

```js
const data = [
  { id: 1, name: '部门A', parentId: null },
  { id: 2, name: '部门B', parentId: 1 },
  { id: 3, name: '部门C', parentId: 1 },
  { id: 4, name: '部门D', parentId: 2 },
  { id: 5, name: '部门E', parentId: 2 },
  { id: 6, name: '部门F', parentId: 3 },
]
// 期望输出：以 id=1 为根的完整树结构
```

**代码架子**

```js
function arrayToTree(items) {
  // TODO
}
```

**参考答案（Map 两遍遍历，O(n)）**

```js
function arrayToTree(items) {
  const map = {}
  const result = []

  // 第一遍：建立 id → 节点映射，同时预置 children 数组
  for (const item of items) {
    map[item.id] = { ...item, children: [] }
  }

  // 第二遍：根据 parentId 组装父子关系
  for (const item of items) {
    const node = map[item.id]
    if (item.parentId == null) {
      // parentId 为 null 或找不到父节点：当作根节点
      result.push(node)
     
    } else {
       // 有父节点：挂到父节点的 children 下
      map[item.parentId].children.push(node)
    }
  }

  return result
}
```

**关键点**

| 点 | 说明 |
|---|---|
| Map 空间换时间 | 两次遍历 O(n)，而非嵌套循环 O(n²) |
| 第一遍预置 `children: []` | 第二遍直接 push，不需要判断是否存在 |
| `map[item.parentId]` 防御 | 父节点不存在时当根节点处理，避免报错 |
| `{ ...item, children: [] }` | 浅拷贝原始数据，不污染入参 |



**常见错误**

```js
// ❌ 嵌套循环，O(n²)
for (const item of items) {
  const parent = items.find(i => i.id === item.parentId)  // 每次都遍历
  ...
}

// ✅ Map 一次查找 O(1)
const node = map[item.parentId]
```

## `树转数组（树扁平化）`

**题目要求**

将树形结构扁平化为数组，去掉 `children` 字段，保留其他字段。

**代码架子**

```js
function treeToArray(tree) {
  // TODO
}
```

**参考答案（迭代 BFS，推荐）**

```js
function treeToArray(tree) {
  const result = []
  const stack = [...tree]  // 用数组模拟队列/栈

  while (stack.length) {
    const node = stack.shift()           // BFS：从头部取（队列）
    const { children, ...rest } = node   // 解构，去掉 children
    result.push(rest)

    if (children && children.length) {
      stack.push(...children)  // 子节点入队
    }
  }

  return result
}
```

**参考答案（递归 DFS，简洁版）**

```js
function treeToArray(tree, result = []) {
  for (const node of tree) {
    const { children, ...rest } = node
    result.push(rest)
    if (children && children.length) {
      treeToArray(children, result)  // 递归处理子节点
    }
  }
  return result
}
```

**关键点**

| 点 | 说明 |
|---|---|
| 解构 `{ children, ...rest }` | 干净地去掉 children，不影响其他字段 |
| BFS vs DFS | BFS（shift/push）按层级输出；DFS（递归）按深度优先 |
| `result = []` 默认参数 | 递归版共享同一数组，不用每层 concat |
| 大树用迭代 | 递归深度过深可能栈溢出，迭代版更安全 |

## `查找树节点路径`

**题目要求**

给定树和目标节点 `id`，返回从根到该节点的路径数组（节点 id 列表）。找不到返回 `null`。

**代码架子**

```js
function findPath(tree, targetId) {
  // TODO
}
```

**参考答案（DFS 回溯）**

```js
function findPath(tree, targetId) {
  function dfs(nodes, path) {
    for (const node of nodes) {
      path.push(node.id)  // 入路径

      if (node.id === targetId) return [...path]  // 找到，返回路径快照

      if (node.children && node.children.length) {
        const found = dfs(node.children, path)
        if (found) return found  // 子树找到，向上透传
      }

      path.pop()  // 回溯：当前节点不在路径上，弹出
    }
    return null  // 当前层未找到
  }

  return dfs(tree, [])
}

// 示例
findPath(tree, 6)  // [1, 3, 6]
findPath(tree, 5)  // [1, 2, 5]
findPath(tree, 99) // null
```

**关键点**

| 点 | 说明 |
|---|---|
| `path.push` / `path.pop` | 回溯模式：进入节点时 push，确认不在路径时 pop |
| `return [...path]` | 返回快照，否则后续 pop 会修改返回的数组 |
| `if (found) return found` | 找到后立即向上透传，不继续遍历 |
| 返回 `null` | 当前层找不到，让上层继续判断 |

**执行过程示意（找 id=6）**

```
dfs([根节点1], [])
  → push(1) → path=[1]
  → dfs([2,3], [1])
    → push(2) → path=[1,2]
    → dfs([4,5], [1,2]) → 未找到 → return null
    → pop(2) → path=[1]
    → push(3) → path=[1,3]
    → dfs([6], [1,3])
      → push(6) → path=[1,3,6]
      → id===6 → return [1,3,6] ✅
```
